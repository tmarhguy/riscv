(America/New_York), crossing 2026-10-02 UTC. Apple Silicon,
Verilator 5.052, xPack RISC-V GCC 13.2.0-2. All evidence below is RTL
simulation; no FPGA or silicon result is implied.

## Result

* IF streams aligned 64-bit instruction parcels in RUN, assembles pairs
  across an eight-byte boundary with two transactions, buffers stalls,
  and drains redirects through IDLE.
* ID has four reads and two writes; EX has two ALU/branch slots. Pair
  dispatch serializes RAW, WAW, and shared-resource conflicts; forwarding
  identifies both producer slots through three-bit selectors.
* Pipeline registers carry both slots with ordered traps, CSR handling,
  and the existing background DIV scoreboard. Misaligned fetch targets
  participate in trap_taken.
* Wishbone test memories return full instruction parcels and sample at
  the falling edge so held-strobe requests receive current-address data.

## Next phases and acceptance gates

1. **Phase 3 — branch prediction:** replace the current slot-A bimodal
   predictor with gshare, BTB, and RAS. Carry per-slot predicted direction
   and target through the pipeline; resolve the older slot first and
   invalidate younger work on a redirect. Check taken/not-taken recovery,
   target mismatches, slot-B branches, calls/returns, and redirect timing
   during memory stalls before measuring prediction improvement.
2. **Phase 4 — RVC:** decode/expand 16-bit instructions, track actual
   instruction lengths, and assemble mixed-length boundary straddlers.
   Cover c.j/c.jr targets and ma_fetch-style alignment behavior; adjust
   alignment traps for the implemented C extension.
3. **Phase 5 — A extension:** implement LR/SC reservations and AMOs with
   LSQ/bus atomicity. Add rv64ua compliance plus reservation invalidation,
   failed SC, and ordering coverage.
4. **Phase 6 — OoO:** integrate rename/PRF, reservation-station issue,
   ROB commit, and LSQ disambiguation with precise recovery and full
   two-wide retirement. Verify dependencies, speculative stores, traps,
   and flush recovery before claiming out-of-order execution.

Each phase requires lint, unit tests, C++ suites, cocotb, RV64 and RV32
compliance with no regressions. Extend compliance for each newly supported
extension. These phases are planned work, not completed Phase 2 features.
