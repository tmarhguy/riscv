[[ch-arch]]
== Architecture

Target: *RV64IMAC + Zicsr/Zifencei*, 2-wide superscalar out-of-order,
Tomasulo with in-order commit. AXI4-Lite native. M-mode precise traps.

=== Pipeline overview

Five programmer-visible stages: fetch, decode/rename/dispatch,
issue/execute, memory, commit. Mispredicts and traps roll back to the
ROB head and redirect fetch.

The commit stage retires up to two instructions per cycle and is the
only point where architectural state becomes visible.
See <<ch-design>> for stage internals and <<ch-if>> for bus behavior.

=== Branch prediction

* gshare predictor with 8K-entry pattern history table.
* 1K-entry branch target buffer plus 16-entry return-address stack.
* BTB miss predicts not-taken; resolution happens in execute.
* Mispredict flushes instructions younger than the ROB branch entry and
  restores the rename checkpoint. Sources: `rtl/rv64xo3_bp.sv`, `rtl/frontend/`.

=== Memory and commit model

* 16-entry LSQ with store-to-load forwarding; stores drain at commit.
* Speculative loads guarded by a conservative store-set conflict predictor.
* AXI4-Lite instruction and data masters; misaligned accesses trap,
  there is no hardware fixup. See <<ch-if>>.
* CSR, `mret`, `ecall`, and `ebreak` retire at the ROB head only,
  giving precise M-mode traps (`mepc`/`mcause`/`mtval` set, redirect to `mtvec`).
